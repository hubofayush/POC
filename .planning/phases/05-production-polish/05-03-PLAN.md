# 05-03 PLAN — Input Guardrails: Content Filters, Denied Topics, PII Masking, Word Filters, Grounding

Goal: close the guardrail gaps vs. the design doc's D5 mandate — hate/insults/sexual/misconduct
filtering, denied-topics deny-list, Presidio masking of input before D3, profanity blocklists on
both directions, embedding-based contextual grounding.

Baseline: prompt-attack (L2 `PromptInjectionGuard`/`SemanticInjectionGuard`) and violence
(L4 `HarmfulContentGuard`, WIP) already covered. Egress already masks PHI; ingress only warns.

## Waves

### Wave 0 — Plan artifacts (0.25h)
- Create 05-03-PLAN.md, update STATE.md (plan 05-03 in progress)
- Commit: `docs(5-3): plan input guardrails phase`

### Wave 1 — Content moderation categories (1.5h)
- **1.1** Extend `layer4_harmful.py` → add `ContentModerationGuard` with per-category lexicon +
  semantic template banks: **hate speech, insults, sexual content, misconduct** (violence stays
  in `HarmfulContentGuard`); all default **block** (`GUARDRAIL_MODERATION_MODE=block`)
- **1.2** Wire into `ingress/pipeline.py` beside `HarmfulContentGuard`
- **1.3** `tests/test_moderation_guard.py`: block cases per category + clean-domain passes

### Wave 2 — Denied Topics (0.75h)
- **2.1** New `DeniedTopicGuard` in `layer4_content.py`: org-agnostic deny-list
  (config `GUARDRAIL_DENIED_TOPICS`, comma-separated keywords) + lexicon matching; **block** default
- **2.2** `tests/test_denied_topics.py`

### Wave 3 — PII/PHI input masking before D3 (1h)
- **3.1** New `PHIInputMaskingGuard`: on detection, run `anonymize_pii()` and write masked text to
  `context["_masked_input"]` — invoke service forwards the masked text to D3 (same
  `_filtered_output` pattern egress uses)
- **3.2** Config `GUARDRAIL_INPUT_PHI_MASK=True` (default on); keep warn-log of raw finding for audit
- **3.3** Tests: raw PHI never reaches forwarded text; masked output passes

### Wave 4 — Word filters (profanity) both directions (1h)
- **4.1** Shared blocklist module `app/core/guardrails/wordlist.py` (leetspeak-normalized matching,
  reuses `_normalise`; curated default set + env/config extendable)
- **4.2** Ingress `WordFilterGuard` — **block** profane user input (layer 2, cheap)
- **4.3** Egress `ProfanityMaskGuard` — **mask** tokens with `[FILTERED]`, write to
  `context["_filtered_output"]`, pass response
- **4.4** `tests/test_word_filter.py` (both directions, leetspeak bypass attempts)

### Wave 5 — Contextual grounding (embedding-based) (1h)
- **5.1** Upgrade `egress/layer3_grounding.py`: add `SemanticGroundingGuard` — cosine similarity
  (reuse `get_encoder`) between output and citation chunks; complements term-overlap
  `CitationCoverageGuard` (the module docstring already names this as the planned enhancement)
- **5.2** Config `GUARDRAIL_EGRESS_GROUNDING_MODE` now honors `block`; tests with fabricated/cited outputs

### Wave 6 — Verification & checkpoint (0.5h)
- **6.1** Wire all into both pipelines; ruff + mypy + pytest (full suite incl. existing WIP
  `test_harmful_guard.py`), restart dev server, smoke
- **6.2** Commit WIP (layer4_harmful, get_encoder cache, pyproject) + feature commit; STATE.md +
  05-03-SUMMARY.md, checkpoint report

## Acceptance Criteria
- Hate, insults, sexual, violence, misconduct, prompt-attack each blocked by a unit test
- Denied topics configurable + blocking; PII masked in input before D3 and on output
- Profanity blocked on input, masked on FM output
- Grounding includes embedding-based check; all gates green
