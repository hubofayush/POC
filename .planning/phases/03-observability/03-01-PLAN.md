# 03-01 PLAN — Observability & Ops

Goal: make the running system observable and operationally sound — Prometheus metrics, liveness/readiness probes, proxy-aware rate limiting, request logging, and hardened Docker packaging.

## Waves

### Wave 0.1 — Plan artifacts (0.25h)
- Create 03-01-PLAN.md, update `.planning/STATE.md` (Phase 3 in progress)
- Commit: `docs(3-1): plan phase 3 observability`

### Wave 1 — Metrics (1h)
- **1.1** Add `prometheus-client` dep; new `app/observability/metrics.py`: `HTTP_REQUESTS` counter (method,path,status), `HTTP_REQUEST_DURATION` histogram (method,path), `HTTP_INFLIGHT` gauge, `GUARDRAIL_DECISIONS` counter (layer,decision,code), `D3_CIRCUIT_STATE` gauge (0/1/2 closed/half-open/open)
- **1.2** `app/middleware/http_metrics.py`: ASGI middleware recording requests/inflight/duration; wire into main.py; `GET /metrics` endpoint (prometheus_client.generate_latest, text/plain)
- **1.3** Wire counters: invoke service records guardrail decisions (block/warn/pass per layer+code); d3_client updates `D3_CIRCUIT_STATE` on state transitions
- **1.4** `tests/test_metrics.py`: middleware increments (200 + 422 paths), /metrics returns expected families

### Wave 2 — Probes (0.5h)
- **2.1** `GET /health/live` (process up, always 200) and `GET /health/ready` (DB reachable via `engine.connect()`; 503 on failure); keep `/health` as-is
- **2.2** `tests/test_health.py`: live 200; ready 200 with DB; ready 503 when DB fails (monkeypatch engine.connect to raise)

### Wave 3 — Proxy-aware rate limiting (0.5h)
- **3.1** Config `TRUST_PROXY_COUNT: int = 0`; `rate_limit.py` key_func: if TRUST_PROXY_COUNT > 0, use rightmost N-1 of X-Forwarded-For (skip last hop), else `get_remote_address`; docs comment on trust boundary
- **3.2** `tests/test_rate_limit_proxy.py`: with TRUST_PROXY_COUNT=1 the login limit keys on the XFF client (exceed limit from different local IPs, proxied identically) — use slowapi testing with client + settings patch

### Wave 4 — Docker packaging (0.5h)
- **4.1** `Dockerfile`: non-root user (`useradd -r`), no COPY of `.env` (env injected via compose), explicit `HEALTHCHECK` (curl-less: python urllib to /health/live), keep 3.12-slim
- **4.2** `docker-compose.yml`: app healthcheck (test/interval/start_period), restart policy, `depends_on: condition: service_healthy` for db
- Verify: config-only review; **docker CLI unavailable in this env — mark build verification as deferred to a machine with Docker**

### Wave 5 — Request logging (0.75h)
- **5.1** `app/middleware/request_log.py`: structlog events `http.request` (method, path, status, latency_ms, client_ip, user_agent) + `http.request.error` for >=500 with exception info; skip /metrics + /health paths; emit at INFO
- **5.2** `tests/test_request_logging.py` (caplog): 200 request logged with path/status; 422 logged; /metrics NOT logged

### Wave 6 — Integration & checkpoint (0.5h)
- **6.1** Full suite + live smoke (restart dev server on new code), curl /metrics + /health/live + /health/ready
- **6.2** `03-01-SUMMARY.md`, STATE.md update, metadata commit, checkpoint report

## Acceptance Criteria
- `py -m pytest -q --no-header` green (existing 113 + new)
- Live: /metrics serves Prometheus families; /health/ready reflects DB state; request logs appear for API calls, not /metrics
- Docker artifacts hardened; build verification deferred (no docker CLI here)
