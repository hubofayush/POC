# 02-01-PLAN — Phase 2: Reliability

Goal: close the reliability gaps of the Phase-1-hardened gateway: tamper-evident
audit chain, persisted traces, no blocking work on the event loop, and a hardened
D3 egress path (timeout/retry/circuit breaker).

## Tasks

### Wave 0 — planning artifacts
- 0.1 Write this plan; update `.planning/STATE.md`. Commit `docs(2-1): plan phase 2 reliability`.

### Wave 1 — schema evolution (prerequisite for 2.2/2.3)
- 1.1 **Test DB isolation** (needed before schema changes): `tests/conftest.py` sets
      `DATABASE_URL` to a dedicated `d5_test.db` BEFORE importing app modules; drop
      stale file at session start. Stops test runs from wiping the dev server's data.
- 1.2 **Alembic migration 02** (`xxxx_reliability_audit_chain_traces`): add
      `audit_log.prev_hash` (String(64), default ""), create `traces` table
      (trace_id PK, org, user_id, action, input_preview, start_time, end_time,
      status, metadata JSON, spans JSON); backfill prev_hash chain for existing rows;
      verify upgrade + downgrade on scratch DB. Commit `feat(2-1): alembic migration 02 ...`.

### Wave 2 — audit hash chaining (dep: 1.2)
- 2.1 `AuditRepository.create_entry`: chain hash `sha256(prev_hash | fields)`; prev_hash
      = last row's hash; module-level asyncio.Lock serializes inserts (documented
      single-process limitation).
- 2.2 `verify_chain()`: replay chain, return `(valid, entries_checked, first_broken_id)`.
- 2.3 `GET /audit/verify` (admin only) exposing it.
- 2.4 Tests: chain continuity, tamper detection (flip a field → broken), empty log valid.
      Commit `feat(2-1): tamper-evident audit hash chaining`.

### Wave 3 — trace persistence (dep: 1.2)
- 3.1 `TraceRepository` (async) persisting traces + spans to the `traces` table.
- 3.2 `Tracer` becomes async facade over the repository (create_trace/create_span/
      end_span/end_trace/get_traces/get_trace); update call sites in
      `app/services/invoke.py` + `app/api/v1/traces.py`.
- 3.3 Tests: trace created → persisted → listed/fetched; org scoping preserved; 404 foreign org.
      Commit `feat(2-1): persist traces to database`.

### Wave 4 — async offload (independent)
- 4.1 `auth.py` login: argon2 `verify_password`/`dummy_verify` via `asyncio.to_thread`.
- 4.2 `invoke.py`: PHI `mask_phi` calls via `asyncio.to_thread` (presidio regex/NLP is blocking).
- 4.3 Tests: existing auth/invoke/phi suites stay green (behavior identical).
      Commit `perf(2-1): offload blocking work from event loop`.

### Wave 5 — egress hardening (independent)
- 5.1 Config: `D3_TIMEOUT_SEC=5.0`, `D3_MAX_RETRIES=2`, `D3_RETRY_BASE_DELAY_SEC=0.25`,
      `D3_CIRCUIT_FAILURE_THRESHOLD=5`, `D3_CIRCUIT_RESET_SEC=30`.
- 5.2 Rewrite `app/integrations/d3_client.py`: injectable async provider (mock stays the
      default), per-call timeout, retry w/ exponential backoff (connect/5xx/429 class),
      circuit breaker (closed/open/half-open), structured logs
      (`egress.d3.retry`, `egress.d3.circuit_opened`, ...). Exceptions: `D3CallError`,
      `CircuitOpenError`.
- 5.3 `invoke.py`: catch D3 failures → end trace failed, audit entry (status="block",
      guardrail_code="D3_UNAVAILABLE"), HTTP 503 (no more raw 500).
- 5.4 Tests (`tests/test_egress.py`): retry-then-success, exhaust-retries error, breaker
      opens after threshold, half-open probe succeeds after reset, timeout honored.
      Commit `feat(2-1): hardened D3 egress with timeout, retry, circuit breaker`.

### Wave 6 — integration & checkpoint
- 6.1 Full suite green; smoke test live against dev server.
- 6.2 `.planning/STATE.md` 100%, `02-01-SUMMARY.md`, metadata commit, checkpoint report.
